# Dogfood trace — HTML-Games PRs #138–#142 post-action review

**Date:** 2026-05-07
**Substrate:** [HTML-Games](https://git.gobha.me/xcaliber/HTML-Games) — five sibling tasks across the **Add feature** and **Cross-game refactor** archetypes, executed back-to-back.
**Editor version under test:** ai-editor `main` HEAD between **1.8.0** and **1.8.3** at session time (each task ran against whatever HEAD was current; these PRs predate the 1.8.4 panel work).
**Mode:** post-action artifact review — the trace below grades what the merged/ready PRs *show* about tool behavior, not a live observation of the tool calls themselves.
**Outcome:** semantics correct on all five PRs; **two cosmetic-litter patterns** identified across them; **one comment-eating artifact** in PR #142 that is the same shape as the 1.8.3 `edit_file` silent-deletion class. One ticket queued for direct fix; one pattern held pending sibling repro; five other observations dropped as out-of-scope.

## Symptom chain (PR #142 — the load-bearing one)

```
intent             insert pause overlay block before existing construction-popup block
expected diff      + <pause overlay block>
                     <!-- Construction Popup Menu -->
                     <div id="constructionPopup">…</div>
actual diff        + <pause overlay block (with its own header comment)>
                     <div id="constructionPopup">…</div>
                                                   ↑ comment "Construction Popup Menu" silently deleted
```

The pause overlay arrived with its own header comment, but the comment that *previously labeled* the construction-popup block disappeared in the same insertion. Both blocks are present and functional — the artifact is *only* the lost comment plus a stray blank line at line 276.

This is the same **shape** as the 1.8.3 silent-deletion regression: an `edit_file` operation lost adjacent context that fell within the model's mental window but outside the explicit edit range. 1.8.3's overlap-aware `EditTracker.checkStale` caught the *re-edit-into-stale-content* case; this artifact suggests a *neighboring case*: insertion-before-existing-block can consume content immediately preceding the inserted block when the model targets the wrong line as the insertion anchor.

> **Note on causation.** Without seeing the live tool-call sequence I can't tell whether the model issued the wrong line range or the editor mis-applied a correct range. The 1.8.3 fix specifically addresses RULE 3 stale-detection during *re-edits*; insertion-eats-neighbor wouldn't trigger that rule because there's no prior edit to detect. Worth a focused root-cause pass before treating this as a fix.

## Grading across the five axes

### 1. Retrieval quality
**Pass (where observable).** PR #141's call was substantively correct: the model identified that `help.js`/`help.css` were dead and the live `openHowToPlay()` system at `forge-defense/index.html:528` was a separate inline implementation. That's the kind of cross-file relevance check `find_relevant_files` is supposed to enable. PR #138 (Pong refactor) similarly handled multi-file scope cleanly.

**Open question for future traces:** these are post-action observations. The trace can't distinguish "retrieval surfaced the right files" from "model already knew the file shape from prior turns in the conversation." Future traces should capture the live retrieval calls per the first trace's open-question.

### 2. Tool-call quality
**Two findings:**

- **(Logic, load-bearing)** PR #142 ate an adjacent HTML comment when inserting the pause overlay block. Same family as 1.8.3 silent-deletion but a different rule — insertion-before, not re-edit-overlap. **Files a ticket** (see "What this trace produced" below).
- **(Cosmetic, pattern under observation)** Trailing blank lines on insertion show up in 4-of-6 files in PR #139 plus snake (#140) plus forge-defense (#141, #142). Consistent enough to suggest the editor's insertion strategy adds a stray newline at certain block boundaries, *but* still cosmetic. **Held pending sibling repro** — if a different cheap-tier model on a different game produces the same litter on equivalent insertions, it's a logic fault worth a 1.8.5 patch. Until then, it's noise.

### 3. Compression behavior
**N/A.** Five short tasks, none crossed the summarizer threshold. No truncation marker fired; no orphan drops. Uneventful.

### 4. Planning quality
**Pass on all five.** Each PR landed the right semantic change for the request: Pong's refactor preserves behavior, snake's high-score wrapper is shape-correct, forge-defense's help-removal correctly identified the dead code path, the back-to-arcade convention is consistent, and the pause feature is functionally complete (pause / resume, blur / visibilitychange handlers wired). The artifacts are at the *editing layer*, not the planning layer.

> One sub-observation: PR #142's pause feature has three real game-UX gaps (focus-trap, blur/visibility race, Esc handling). These are forge-defense bugs Jeff would file regardless of dogfood status — they're not editor artifacts and don't belong on the ai-editor stress-test ledger. Filing them under html-games, not here. Dropping them from this trace deliberately.

### 5. Cost-quality tradeoff
**Right side of the knee.** Five working PRs landed at cheap-tier cost. The artifacts are litter, not failure. This is what the dogfood matrix calls a **clean cheap-tier outcome** — quality didn't fall off the spend curve, and the litter is detectable + fixable downstream. Contrast with the first trace's *under-spend with task failure* shape; this session is an example of the opposite: cheap-tier ran the table.

Per-turn `prompt_tokens` / `cached_tokens` not captured this session — same gap as the first trace. **Carry-forward action:** before declaring a multi-PR session complete, write a session-end cost export to disk so subsequent traces can pin "cheap-tier ran the table" with numbers instead of an eyeball.

## What this trace produced

1. **One ticket queued for ai-editor.** Investigate edit_file's insertion-before-existing-block path for adjacent-content consumption (PR #142 / `<!-- Construction Popup Menu -->` case). Root-cause first; cure second; regression test pinning the comment-survival case third. Same discipline as the 1.8.3 fix. **Do not ship a 1.8.5 from this trace alone** — sibling repro needed. If the next sibling-task session reproduces it on a different cheap-tier model and a different game, file as a logic fault and cure.

2. **One pattern under observation.** Trailing-blank-line litter on insertion. Pattern observed across 4 PRs / multiple files / single session. **Hold pending sibling repro.** If a different cheap-tier model on a different game produces the same litter on equivalent insertions, file. Otherwise close as noise.

3. **Five forge-defense game-UX observations dropped from this trace** as out-of-scope. They belong on the html-games tracker (focus-trap, blur/visibility race, Esc handling, comment restoration as direct fix, whitespace cleanup as a one-shot). Filing them here would inflate the dogfood signal with non-editor work.

4. **Three "stress-test fodder" tickets dropped entirely.** Pre-staging probes ("standardize back-to-arcade", "extract inline tutorial logic", "audit unused CSS") inverts the dogfood premise — the program runs *on real tasks Jeff is already doing*, not synthetic ones. If those refactors come up organically in future PRs, the editor will surface its handling of them; pre-staging is wasted spend.

## What this trace did *not* produce (deliberately)

- **Cure-PRs against ai-editor.** Per ROADMAP "trace > PR" — observations land first; cures land only after sibling repro. The 1.8.3 silent-deletion took two HTML-Games sessions before the fix landed; this artifact is one session in.
- **Direct fix-PRs against html-games.** The user asked for editor stress-test signal, not html-games maintenance. Cosmetic litter cures belong on the html-games tracker.
- **A model attribution table.** The five PRs ran across the cheap-tier rotation; per-PR model assignment isn't pinned in this trace. Future traces in the artifact-review shape should capture model-per-PR at session start so the logic-vs-LLM split has the data it needs.
